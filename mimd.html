[04] MIMD — MULTIPLE INSTRUCTION, MULTIPLE DATA

The architecture powering all modern desktop, mobile, server, and supercomputer CPUs (Intel Core, AMD Ryzen, Apple Silicon, ARM, Xeon). Each Processing Element possesses its own independent Control Unit, Program Counter, and ALU. Cores execute completely different instruction streams on distinct data items simultaneously.

// MEMORY ARCHITECTURES & BUS ARBITRATION CONTENTION

Shared-Memory (SMP / UMA): All cores share a unified memory bus. When multiple cores execute memory instructions (LOAD or STORE) in the same clock cycle, the hardware bus arbiter grants access to one core while others stall in a wait state.

Distributed-Memory (Clusters / MPPs): Each processor has its own private physical memory. Cores never stall each other's memory buses, allowing scaling to thousands of cores (e.g., Frontier Supercomputer), but require message passing (MPI) across inter-node networks.

SHARED VS DISTRIBUTED MEMORY
[SHARED MEMORY (SMP / UMA)]:
Single unified memory space. Communication is implicit via memory writes. Bottleneck: memory bus saturation above 16-32 cores.

[DISTRIBUTED MEMORY (MPP / CLUSTERS)]:
Each node has isolated RAM. Zero bus contention between nodes. Communication requires explicit network packets (MPI).
REAL-WORLD PRODUCTION DEPLOYMENTS
[Intel Xeon & AMD EPYC]: Up to 128 cores per socket with NUMA multi-channel DDR5 controllers.

[Apple M-Series Ultra]: UltraFusion 2.5 TB/s inter-die interconnect joining two Max chips into a single unified MIMD entity.

[Frontier Supercomputer]: 9,472 nodes with 600,000+ total cores executing MPI massively parallel workloads.

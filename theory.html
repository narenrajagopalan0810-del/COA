[06] FLYNN'S TAXONOMY THEORY REFERENCE

Proposed in 1966 by Michael J. Flynn, this seminal classification categorizes all digital computer architectures based on the multiplicity of concurrent Instruction Streams and Data Streams. Use this guide for theoretical study, system design principles, and technical architecture defense preparation.

SYSTEM ARCHITECTURE REFERENCE
FLYNN'S 2 × 2 ARCHITECTURAL MATRIX
[QUADRANT 01]
1 INST / 1 DATA STREAM

SISD // VON NEUMANN

Single Control Unit fetches one instruction to process one data element. Sequential uniprocessor execution without hardware concurrency.

Examples: Intel 8086, PDP-11, ARM Cortex-M0
[QUADRANT 02]
1 INST / N DATA STREAMS

SIMD // VECTOR ARRAY

Single Master CU broadcasts one instruction to N lockstep PEs. Massive uniform vector throughput with mask predicated branching.

Examples: NVIDIA CUDA Warps, AVX-512, Cray-1
[QUADRANT 03]
N INST / 1 DATA STREAM

MISD // STREAM PIPE

N independent CUs operate concurrently on one data stream. Pipelined systolic processing and hardware fault voting.

Examples: Space Shuttle TMR Voter, TPU Systolic Arrays
[QUADRANT 04]
N INST / N DATA STREAMS

MIMD // MULTICORE

N independent CUs execute separate instruction streams on independent data sets. Shared bus arbitration vs cluster networks.

Examples: Modern Multicores (Intel, AMD, Apple), Supercomputers
SISD UNIPROCESSOR ANALYSIS

In a pure SISD system, instructions execute sequentially. While superscalar architectures execute multiple instructions per cycle using out-of-order execution, they remain functionally SISD because they uphold the illusion of a single sequential instruction stream.


[ADVANTAGES]: Simple programming model, deterministic debugging, no concurrency races.
[BOTTLENECK]: Strictly constrained by Dennard scaling limits and the Von Neumann memory wall.
SIMD VECTOR & GPU WARP ANALYSIS

SIMD amortizes instruction fetch/decode energy across dozens of ALUs. However, when branches occur (if/else), SIMD hardware must serialize both execution paths using predication masks, idling cores that do not participate.


[ADVANTAGES]: Exceptional compute density and energy efficiency for matrices/graphics.
[BOTTLENECK]: Branch divergence penalizes performance heavily on irregular logic.
MISD PIPELINES & REDUNDANCY

Why is MISD rarely seen in consumer devices? General-purpose software either parallelizes data items (SIMD) or splits independent tasks (MIMD). MISD is engineered for two specific high-reliability or high-throughput domains:


1. Triple Modular Redundancy (TMR): Aerospace flight computers broadcast sensor inputs to 3 diverse PEs with a majority voter to mask cosmic ray bit-flips.
2. Systolic Tensor Arrays: Matrix multiply engines where activations stream through ALU cascades without round-trip memory writes.
MIMD MEMORY TOPOLOGIES

MIMD systems are split into two foundational memory paradigms:


[SHARED MEMORY (SMP / UMA)]: All cores share a unified address space. Simple multi-threaded programming, but memory bus contention and cache coherence traffic limit scalability to tens of sockets.

[DISTRIBUTED MEMORY (CLUSTERS / NUMA)]: Each node maintains private physical memory; communication happens via explicit message passing (MPI). Scalable to millions of cores.
TECHNICAL EXAMINATION & DEFENSE Q&A GUIDE
Q1: Why does SIMD execute faster than shared-memory MIMD on Vector Addition in FlynnSim?

Answer: SIMD uses a single broadcast Control Unit and parallel vector memory banks, eliminating control instruction overhead and shared-bus arbitration. In shared-memory MIMD, multiple independent threads contend for the central memory bus during store operations, causing bus contention stalls.

Q2: What is SIMD branch divergence, and how does FlynnSim demonstrate it?

Answer: Because SIMD shares a single instruction sequencer broadcasting to all PEs, it cannot follow two branches simultaneously. PEs failing the condition are masked off (MASK=0) and idle while the THEN block runs, and vice-versa for the ELSE block. FlynnSim records these idle cycles in the Divergence Penalty Meter.

Q3: How does FlynnSim handle vector lengths that are not exact multiples of the PE count?

Answer: FlynnSim employs tail predication masking (MASK_EVAL PE_LT #rem). On the final iteration, only PEs whose IDs are less than the remainder elements remain active; the others are masked off, preventing invalid memory writes.

Q4: What is the core difference between Amdahl's Law and Gustafson's Law?

Answer: Amdahl's Law models strong scaling (fixed problem size), where speedup is strictly bounded by the serial fraction 1 / (1 − p). Gustafson's Law models weak scaling (problem size scales proportionally with core count), where speedup grows linearly as S(N) = s + N(1 − s).
